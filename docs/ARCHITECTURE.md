# Architecture and adding designs

The catalog is an Astro 7 static app using content collections with the glob loader. Public identity lives in a JSON file consumed by components and the Node tooling. Routes and content are shared; each design owns its homepage, interior-page art direction, and theme styles. Static content means low hosting requirements and no public API secrets. Content authoring runs in a local agent/Node process or GitHub Actions, separately from visitor requests.

- templates/ID/template.json: machine-readable design identity, description, version, and page coverage.
- templates/ID/Home.astro: home composition. Reference shared agent config and Services; do not hardcode personal data.
- templates/ID/pages.ts: headings and image imports for buyer, seller, about, and journal layouts. A design may set an optional contact direction. Contact uses the About art and shared heading by default. The shared DesignPage component renders these with the common guides, agent identity, and blog content.
- templates/ID/theme.css: design tokens and composition styles. Core shared CSS handles common pages, navigation, and responsive accessibility basics.
- src/selected-template.ts: the catalog’s default design import. Preview routes select each catalog design.
- src/lib/seo.ts and seo-policy.mjs: shared page metadata, connected JSON-LD, script-safe serialization, and route indexing policy. Layout renders this once per page. src/lib/media.ts performs build-time WebP/responsive transforms used by all eight designs. Each pages.ts exports homeArt for social previews and hero/poster preload as well as its interior-page art.
- catalog-previews/ID/PAGE.webp: catalog-only screenshots for the expandable page preview grid. Capture the top of each rendered page at 1440×900 after fonts and images load, trim the native scrollbar, then resize to 640×400 WebP. Refresh these when a page’s design changes. The export allowlist excludes this directory.
- scripts/create-site.mjs: deliberate export allowlist and import rewriting. The output has src/design/ and no catalog or alternate designs. It copies .github/owner-workflows/ci.yml as the export's only active workflow, rather than inheriting the catalog's .github/workflows/. The optional draft workflow is copied to docs/examples/content-draft.yml and runs only after explicit activation.

## Add a design

Create its folder and manifest, Home.astro, pages.ts, and theme.css. Supply paper, ink, muted, accent, line, and display CSS variables. Use meaningful headings, good contrast, and mobile layouts. Keep primary shared-page links absolute from the site root. Include original/licensed assets and document their terms. The preview route, exporter and export tests discover IDs from manifests. Add the design to the README. Keep design media alongside its Home component and import it with `?url`; Vite emits the selected assets at build time. Document stock and generated asset provenance in `media/CREDITS.md`. An optional `preview.jpg` is for the catalog only. Add full-page browser QA and build the exported site independently. Theme changes should not require duplicating config or the blog pipeline.

The interior pages share semantic sections but vary their layout, typography, and imagery per design. Catalog links stay within the active theme for these pages and published articles. Contact details come from the shared agent config. Privacy and accessibility use shared pages. No package publication, remote installer, visual CMS, IDX/MLS feed, or deploy bot is implied. A future CLI package can wrap the exporter once its release/version/update contract is established. The public catalog builds one source ZIP per design; visitors can download just their choice without cloning the catalog. A sparse checkout and the exporter provide a fallback. See docs/GET-STARTED.md and docs/GITHUB-PAGES.md.

The shared homepage portrait uses `portraitUrl` from agent config. Demo sites without a configured headshot use `src/assets/demo-agent-portrait.jpg`, an AI-generated fictional portrait.
